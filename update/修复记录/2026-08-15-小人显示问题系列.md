# 小人显示问题系列（修复记录）

**日期**：2026-08-15

## 问题与修复时间线
1. **只显示一半** → 模型默认缩放 0.1 超出画布：stage 360×640 + modelScale 0.06（config 可调）
2. **按钮被画布遮挡** → oml2d 使用 z-index 9997~9999 内联样式且反复重写：一度用 !important + MutationObserver 压制，但引入新问题
3. **小人整个消失** → 隐藏蓝色气泡的扫描把舞台也误藏（多次变体）
4. **决定性根因** → 查打包源码与类型声明确认：0.19.3 的 Oml2dProperties **没有 stageElement 属性**，且舞台/画布/气泡全部挂载到 `options.parentElement`
5. **最终方案** → 自建 `stage-host` 容器传入 parentElement：显示/隐藏只控制容器；隐藏内置蓝色气泡改为**按元素 id 精确白名单**（oml2d-tips/menus/statusBar/loading/status），舞台/画布/全局容器明确排除，并加 `healStage()` 自愈（主动清除舞台上的 display:none 注入）
6. **画布 0×0** → 隐藏状态下初始化导致 Pixi 测量为 0：恢复显示/初始化后多次重设尺寸 + 派发 resize
7. **偏好记忆坑** → 曾点过 🙈 会持久隐藏小人：召唤按钮改为醒目的带文字按钮「🐣 召唤小人」

## 经验教训
- 与第三方库的 DOM 做斗争前，先读它的类型声明与打包源码确认 API 与挂载方式
- 隐藏逻辑只允许"精确命中已知目标"，绝不做范围扫描
